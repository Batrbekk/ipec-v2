# Управление сайтом IPEC Energy Kazakhstan

Админка находится по адресу `/admin` на том же домене, что и сайт. Для входа используется пароль администратора. Тексты, контакты и медиа меняются без редактирования кода и без новой сборки сайта.

## Работа в редакторе

1. Откройте `/admin` и войдите с выданным паролем.
2. Выберите раздел и язык: RU, KZ или EN. Каждый перевод редактируется отдельно; автоматического перевода нет. Поиск помогает найти нужный текст.
3. Измените поля. В списках услуг можно добавлять и удалять пункты. В теме письма сохраните `{name}` и `{company}`: они подставляют имя и компанию отправителя.
4. В разделе «Фото и видео» замените нужный файл. Контакты и медиа общие для всех языковых версий.
5. Нажмите «Опубликовать изменения». После успешной публикации новые данные используются при следующем открытии или обновлении сайта. Все подготовленные правки во всех трёх языках публикуются вместе.
6. Откройте сайт через кнопку в редакторе и проверьте изменённые разделы и языки.

Поля содержат обычный текст. HTML и произвольные подстановки не поддерживаются. Заголовок вкладки, описание для поиска и подпись логотипа находятся в разделе «Название и описание». Тексты уведомлений по почте — в «Форма и письма».

До публикации правки хранятся только в открытой вкладке. Загрузка файла добавляет его в черновик, но сама по себе не заменяет файл на сайте. Перед закрытием вкладки опубликуйте изменения или скачайте копию. Раздел команды и некоторые исторические тексты сохранены в редакторе; изменение их значений не включает скрытые секции сайта.

При одновременной работе в двух вкладках публикация устаревшей версии возвращает конфликт `409`. Скачайте свой черновик, нажмите «Загрузить опубликованную версию» и перенесите нужные правки. Конфликт не перезаписывает чужую публикацию.

Сессия действует восемь часов. Если она завершилась во время редактирования, войдите в новой вкладке и повторите публикацию, сохранив исходную вкладку с черновиком. После работы используйте кнопку выхода.

## Изображения и видео

| Тип | Форматы | Максимальный размер |
| --- | --- | --- |
| Изображение, логотип, иконка | JPG/JPEG, PNG, WebP, AVIF, GIF, ICO | 10 МБ |
| Видео первого экрана | MP4, WebM | 250 МБ |

SVG-загрузки не принимаются. Для нового логотипа используйте PNG или WebP с прозрачным фоном; исходные SVG-логотипы остаются доступными через кнопку возврата исходного файла. Для иконки подходят ICO или квадратное изображение PNG.

На сайте предусмотрены два логотипа, фоновое видео, фон раздела «О нас», пять изображений услуг, семь фотографий проектов и иконка вкладки. Кнопка возврата исходного файла меняет черновик; для применения требуется публикация.

Загрузка идёт из браузера напрямую в Vercel Blob с временным разрешением сервера. Это позволяет загружать видео без ограничения размера тела обычной Vercel Function. Дождитесь завершения индикатора загрузки. Видеофон воспроизводится без звука; рекомендуется MP4 с H.264 и размером файла, подходящим для мобильного интернета.

Изображения и видео хранятся в **публичном** Blob-хранилище. JSON с текстами, резервные версии и счётчики попыток входа — в отдельном **приватном** хранилище. Сайт получает тексты через сервер. Содержимое редактора всё равно предназначено для посетителей: пароли, SMTP-секреты и другие приватные данные в поля содержимого не вводятся.

## Настройка Vercel

Используйте Node.js **22** в Project Settings → Build and Deployment. У текущей версии обработки изображений есть требование Node.js не ниже 20.9; Node.js 22 подходит всему проекту.

1. Создайте или подключите через Storage два хранилища Vercel Blob: **публичное** для медиа с переменной `BLOB_READ_WRITE_TOKEN` и **приватное** для CMS с переменной `CMS_BLOB_READ_WRITE_TOKEN`. Для второго подключения задайте префикс переменных `CMS_BLOB`. Значения должны быть токенами разных хранилищ с соответствующим режимом доступа.
2. Из локальной папки проекта запустите генератор доступа:

   ```bash
   node scripts/setup-admin.mjs
   ```

   Скрипт создаёт `.admin-private/credentials.json` с паролем и серверными значениями, а также `.admin-private/access.txt` для передачи доступа. Используйте пути, которые он сообщает; пароль храните в менеджере паролей. Скрипт не перезаписывает уже созданный доступ. Для нового комплекта можно указать другой приватный каталог первым аргументом. Не добавляйте эти файлы в Git и не вставляйте их содержимое в публичные логи, задачи или PR.
3. Перенесите необходимые значения окружения в Vercel Project Settings → Environment Variables. Пароль для входа пользователю передаётся отдельно; на сервер загружается его хеш.
4. Выполните новый deployment. Изменение переменных окружения применяется только к новому deployment; обычная публикация текстов в админке его не заменяет.
5. Откройте `/admin`, войдите и проверьте публикацию. После подключения хранилища новые изменения сохраняются между deployment и перезапусками.

| Переменная | Назначение |
| --- | --- |
| `ADMIN_PASSWORD_HASH` | Хеш пароля в формате `scrypt:<salt hex>:<key hex>`, созданный генератором |
| `ADMIN_SESSION_SECRET` | Независимый случайный секрет сессии: Base64, минимум 32 байта после декодирования |
| `BLOB_READ_WRITE_TOKEN` | Серверный токен подключённого публичного Blob-хранилища |
| `CMS_BLOB_READ_WRITE_TOKEN` | Серверный токен отдельного приватного Blob-хранилища для JSON, истории изменений и ограничений входа |
| `ADMIN_ORIGIN` | Необязательно: единственный разрешённый origin админки, например `https://www.ipec-energy.com`, без пути. Если не задан, разрешён текущий origin запроса |
| `EMAIL_USER` | Учётная запись Gmail для отправки заявок |
| `EMAIL_PASS` | Пароль приложения Gmail |
| `CONTACT_RECIPIENT` | Необязательно: адрес получения заявок. По умолчанию `info@ipec-energy.com` |

Все эти значения используются только на сервере; не добавляйте к ним префикс `NEXT_PUBLIC_`. Публичный email в контактных данных сайта не меняет получателя заявок: получатель задаётся отдельно через `CONTACT_RECIPIENT`.

Для Preview и Production задавайте окружение осознанно. В приватном хранилище Production использует документ `cms/site.json`, Preview — `cms-preview/site.json`. Если разные preview-deployment подключены к одному приватному хранилищу, они используют общий preview-документ. Заданный `ADMIN_ORIGIN` должен соответствовать домену, с которого выполняется вход; значение основного домена не подходит для другого preview-домена.

Приватное хранилище обязательно для JSON: оно позволяет читать актуальные данные в обход CDN-кеша. Сервер запрашивает несжатый ответ, чтобы ETag чтения совпадал с ETag условной записи. Это обеспечивает публикацию после чтения и предотвращает перезапись изменений из другой вкладки. Публичный токен медиа не используется как запасной токен CMS.

Если авторизация или хранилище не настроены, административная публикация недоступна. Публичный сайт продолжает показывать исходные материалы. При временной ошибке чтения хранилища публичный сайт также использует исходные материалы; админка сообщает ошибку, чтобы не сохранить данные поверх неизвестной версии.

## Локальная разработка

После установки зависимостей и генерации доступа добавьте `ADMIN_PASSWORD_HASH` и `ADMIN_SESSION_SECRET` из приватного JSON в локальный `.env.local`. Генератор не загружает переменные в работающий процесс. Для локального `ADMIN_ORIGIN` используйте origin сервера разработки, например `http://localhost:3000`, или не задавайте эту переменную; production-origin из сгенерированного JSON локально не подходит. Затем запустите `yarn dev`.

Локально можно использовать приватный Blob через `CMS_BLOB_READ_WRITE_TOKEN` либо указать `CMS_LOCAL_STORE` — путь к отдельному каталогу для JSON-документов. На Vercel этот файловый режим отключён. Держите каталог локального хранилища вне Git; не используйте его как production-хранилище.

Файловый режим подходит для проверки входа, публикации текстов и конфликтов. Загрузка медиа всё равно требует `BLOB_READ_WRITE_TOKEN`, поскольку файлы передаются в Blob напрямую из браузера. После изменения локальных переменных перезапустите сервер разработки.

`yarn test` проверяет авторизацию, валидацию и файловый режим без внешних запросов. Для проверки реального приватного Blob задайте `CMS_BLOB_READ_WRITE_TOKEN` и `RUN_BLOB_STORAGE_TESTS=1`, затем запустите `yarn test`. Дополнительная проверка создаёт только случайный документ в `cms-qa/`, проверяет чтение и конкурентное сохранение большого JSON и удаляет собственный тестовый документ.

## Копии и восстановление

«Скачать копию» экспортирует JSON текущего черновика, включая все три языка, настройки контактов и ссылки на медиа. Это резерв содержимого, а не архив самих изображений и видео. Храните важные исходные медиа отдельно.

Перед каждой публикацией сервер сохраняет предыдущий документ в `cms/history/` или `cms-preview/history/` приватного хранилища. Не удаляйте публичные медиафайлы, на которые ссылаются нужные версии содержимого. В интерфейсе нет кнопки импорта JSON: для восстановления разработчик переносит значения из копии через редактор либо использует авторизованный API с актуальным ETag. Не заменяйте рабочий документ вручную во время чужой публикации.

При переносе существующей CMS из публичного хранилища скопируйте актуальный `cms/site.json` в приватное хранилище до переключения окружения. Ссылки на публичные медиа менять не нужно. После проверки новой публикации старые JSON-копии можно удалить из публичного хранилища.

Для смены доступа создайте новый хеш пароля и новый секрет сессии, обновите обе переменные в Vercel и выполните deployment. Смена секрета завершает ранее выданные сессии. Файлы с паролями и токенами никогда не коммитятся.
